### 关键设计：三类处置而非二分

预检把产物分三类，依据是"我们能确定什么"：
1. 内核模块（有 `.modinfo`）→ vermagic 精确比对
2. ELF → `e_machine` 架构比对
3. **认不出 → 放行**

第 3 类是既有测试逼出来的：原实现把"打不开/不是 ELF"判失败，结果 3 个既有
CLI 测试全红（它们的测试资产是文本不是 ELF）。但真问题是设计缺陷而非测试：
现实里有 shell/python 脚本、jar 等非 ELF 产物，判失败是**假阴性**——直接把
本来能用的组件推掉。假阴性比漏检更糟：漏检最多装完再报错，假阴性让合法装载
永远失败。已补 3 条测试守住（非 ELF 放行、空文件放行、真 ELF 仍拒）。

# P9 ferc bench 接真实装载（2026-11-25）

此前 `ferc bench` 的 Runner 是度量骨架，`elapsed_ms` 恒为 0、成败由"形态是否被
节点支持"决定。本轮接上真实装载。

## 改动

- `internal/cli/bench.go` 新增 `realBenchRunner(env, info, comp, faults)`：
  每个组合用**独立临时数据根目录**（`os.MkdirTemp` + `defer RemoveAll`）跑完整
  `install.New + resolve.Resolve + Apply`。复用同一个 root 会让后一个组合看到
  前一个的残留状态，"成功率"就不再是这个组合自己的成绩。
- `--real` 开关：不加时仍走度量骨架（零副作用）；加了才真下载、真注册、真起进程。
- 检查顺序按"前提的强弱"重排：**网络 > 形态兼容 > 组件与实验形态是否对得上**。
  网络在最前是因为它是物理前提——介质不在场时讨论"这个组件适配吗"没有意义。
- `stageOf` 新增 `isNetworkErr`：网络类失败（connectex / connection refused /
  i/o timeout / TLS handshake / no route to host / 介质不在场…）优先归到
  `download`。现场最常见的一类失败就是取不到包，不优先识别会让阶段分布失真。

## 实跑验证（真实二进制）

无代理时 `--real`：`elapsed_ms=21058`、阶段 `download`（真实网络超时）。
带代理时：走到 resolve（274ms 取到清单）后因 `DontCrack4Windows` release 403
失败——这是**真实情况**：Windows 无原生保活能力，`resolve` 必然带上 dontcrack
依赖，而那个仓的 release 取不到。

同一台机器上单独跑 `ferc install simple-web-shell --no-start` 成功（2 个组件、
凭据落 0600），证明 Runner 走的确实是同一条真实装载路径。

## 诚实边界

- `--real` 的成功率**依赖目标仓的 release 可达性**。DontCrack4Windows 当前
  403，因此 Windows 上的矩阵必然失败；这不是代码缺陷，是现场事实。
- 需要网络的测试用 `testing.Short()` 跳过，CI 无外网时不会红。
- 论文引用矩阵数据前，须在**目标平台**上实跑一遍，不能拿开发机结果代替。

# P10 F3 非常驻测试跨平台化 + 修掉一个一直藏着的 panic（2026-11-25）

## 背景

原 F3 测试带 `//go:build linux`，**从来没在开发机（Windows）上跑过**。
本轮把它拆成平台无关 + Linux 专属两层，平台无关部分立刻抓出一个真 bug。

## 改动

| 文件 | 内容 |
|------|------|
| `internal/install/residency_test.go` | 公共支撑（无平台标签）：`ResidentGuard`、`Snapshot()`、`Check()`、`runEmptyApply`、`hostInfo` |
| `internal/install/residency_common_test.go` | 平台无关测试 5 条：goroutine 不净增长、20 次不累积、空计划成功、nil 计划不 panic、guard 自身能检出增长 |
| `internal/install/residency_linux_test.go` | Linux 专属：`/proc/*/comm` 枚举断言无 ferc + 哨兵进程存亡 |

判据只认 goroutine 数：活跃 ticker 数、打开的 fd 数 Go 没有可靠公开 API，
用不可靠判据做断言比没有断言更糟（偶发假红会让人学会忽略整条测试）。

## 抓出的真 bug：Apply(nil) panic

`Apply` 第一行就解引用 `plan.Warnings`，传 nil 直接崩。它一直藏着，因为
唯一传 nil 的测试带 `//go:build linux`，从没在开发机上跑过——**"只有 CI
跑的测试"等于没测**。已修为"nil 当作什么都没要装"，并补回归测试
`TestApplyNilPlanDoesNotPanic`。

## 顺带修的问题

守护测试 `TestResidentGuardDetectsGrowth` 最初只起 1 个 goroutine，正好落在
`Check` 刻意保留的 +1 余量内，导致这条"证明 guard 有效"的测试假通过。改为起
3 个。

## 验证

```

go vet ./...          无输出
go test ./...         13 包全绿（install 4.8s，含新 5 条）
GOOS=linux GOARCH=amd64 go test -c   OK

```

**仍未 Linux 实跑**：`/proc` 枚举与哨兵进程那两条只有 Linux 真机能验。本机

# P13 Linux 运行时实测交给 CI（2026-11-25）

## 背景

`/proc` 枚举、哨兵进程、真实 probe 这三类测试带 `//go:build linux`，在
Windows/macOS 开发机上根本不编译。本机无 QEMU、WSL 枚举挂起（`wsl -e`
与 `wsl --status` 均 40s 无输出，已试 4 次），因此实跑只能靠 CI。

## 改动

两个仓各加一个 `linux-runtime` job（`runs-on: ubuntu-latest`）：

- **FERC**：显式跑 F3 两条（`TestRuncoreIsNotResident` /
  `TestInstalledServiceSurvives`）+ `internal/probe`（AIO 侧的，不适用，
  见下）。
- **AIO**：显式跑 `internal/probe` + `TestFercExecutor`（exec 调 ferc 的真实
  链路，这条不依赖 /proc，Windows 上也能跑，放 Linux job 是为了让整条链在
  Linux 上再确认一次）。

单拉一个 job 而不是混在 `go test ./...` 里：混在一起看不出哪几条真跑了、
哪几条因为构建标签被跳过——而那几条恰恰是本课题"非常驻"立论的唯一验证。

## 本地能验的与不能验的

已本地验证：
- 两个 YAML 均能被 `yaml.safe_load` 解析，job 列表正确。
- `GOOS=linux go test -c` 对 `internal/install`、`internal/probe`、
  `cmd/aio` 全部编译通过，且 `strings` 确认目标测试名确实编进了二进制
  （不是被构建标签排除掉）。
- CI 里 `-run` 写的测试名与真实测试名一致。
- `TestFercExecutor` 5 条在 Windows 上实跑通过。

**未验证**：这三类测试在 Linux 上的**运行结果**。需等 CI 跑完才知道。这是
环境限制（无 QEMU/WSL/docker），不是代码缺口。

这消除了"尚未实现"清单里最大的一项——"非常驻"这一立论现在有 Linux 实测证据，
不再只是交叉编译验证。

## 修掉的问题

| # | 现象 | 根因 |
|---|---|---|
| 1 | FERC 的 `linux-runtime` job `setup failed` | **CI 配置错**：该 job 里跑 `./internal/probe/`，但 probe 是 AIO 仓的包，FERC 仓里没有。已删该 step。 |
| 2 | AIO `TestPortListeningIPv6Only` 返回 false | **代码 bug**：`scanListening` 按行号跳过第一行当表头，但表头行第四列不是 `0A`、本来就会被状态判断挡掉。按行号跳过反而让"没有表头的内容"丢掉第一条数据。 |
| 3 | AIO `TestCPUPercentSecondCallComputesDelta` 期望 30% 实得 20% | **测试 bug**：Δ200 tick × 0.01 s/tick = 2s，不是注释写的 3s。代码算的 20% 是对的。 |
| 4 | AIO `TestStore_KeepFilesZeroTruncates` 报 78 字节 | **测试 bug**：`ents[0]` 不一定是 `cap.log`，Linux 上是 `config.json`。改为 `os.Stat` 明确指定。 |
| 5 | AIO `readKmsg` 取到最旧的 N 条 | **代码 bug**：边读边 break，与 `KernelLogTail` 的"最新 N 条"语义相反。改为读完再取尾部。 |
| 6 | AIO `KernelLogTail` 错误链丢 `ErrNoDmesg` | **代码 bug**：用 `%v` 而非 `%w` 包装。 |
| 7 | AIO `CPUPercent` 永远报"PID 已复用" | **代码 bug**：构造 `cpuSample` 时漏了 `starttime`，首次基线是零值，第二次必然误判。 |
